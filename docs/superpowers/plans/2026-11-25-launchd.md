# Unattended Runs with launchd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three launchd user agents (poller kept alive under `caffeinate -i`, hourly catch-up compaction, daily static sync) installed from versioned templates, plus a `--pending` mode for `mbta-compact`.

**Architecture:** `mbta-compact --pending` scans bronze for closed hours without silver and compacts each through the existing `compact_hour`. Plist templates in `ops/launchd/` hold one placeholder, `@REPO@`, filled by `install.sh` from the script's own location; `--render-only <dir>` lets pytest check the rendered plists on Linux CI. A runbook in `docs/operations.md`.

**Tech Stack:** Python 3.12, uv, pytest, bash, launchd (`launchctl bootstrap/bootout`, `plutil`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-launchd-design.md`

## Global Constraints

- No new dependencies; `pyproject.toml` unchanged.
- Labels exactly `io.github.eldiego5599.mbta.poller`, `io.github.eldiego5599.mbta.compact`, `io.github.eldiego5599.mbta.static`; installed file `~/Library/LaunchAgents/<label>.plist`.
- `@REPO@` is the only placeholder. No absolute path of this Mac in any committed file.
- Logs: `@REPO@/data/logs/poller.log`, `compact.log`, `static.log` (stdout and stderr to the same file).
- Close grace stays `compact.CLOSE_GRACE` (5 minutes); compaction agent at minute 10; static agent at 04:00 local.
- Code, comments, docs and commits in English; no emojis; in prose no em dashes, guillemets, middle dots or double hyphens; commit messages imperative, brief, formal, no `Co-Authored-By` line; never `--no-verify`.
- `uv run pytest` and `uv run ruff check && uv run ruff format --check` pass at the end of every task.
- Never touch `data/`, never run `launchctl`, never write to `~/Library/LaunchAgents` during the tasks. Installation is done by the main session after review.

## Review Focus

1. A repo path with spaces must render correctly (agents at `/Users/x/My Projects/repo` are common). Pinned in Task 2 by copying the scripts under a directory with a space.
2. A repo path with `&`, `<` or `>` would produce invalid XML; install must refuse with a message and write nothing. Pinned in Task 2.
3. The compact agent runs at install time, possibly before the poller wrote anything: `--pending` with no `bronze/` directory must exit 0 with a message, not 2. Pinned in Task 1.
4. A Mac asleep for many hours: on wake, every closed hour without silver is compacted, oldest first, and the hour still open is left alone. Pinned in Task 1.
5. One unreadable hour must not block later hours and must stay pending for the next run. Pinned in Task 1.

- If nothing was pending for any feed: print `nothing pending`.
- Return `EXIT_FAILED` if any hour failed, else 0.

### Task 2: launchd templates and install scripts

**Files:**
- Create: `ops/launchd/poller.plist.template`, `ops/launchd/compact.plist.template`, `ops/launchd/static.plist.template`, `ops/launchd/install.sh`, `ops/launchd/uninstall.sh` (both executable, `#!/usr/bin/env bash`, `set -euo pipefail`)
- Test: `tests/test_launchd.py`

**Interfaces:**
- Consumes: console scripts `mbta-poller`, `mbta-compact --pending` (Task 1), `mbta-static`.
- Produces: `install.sh [--render-only DIR]`, `uninstall.sh`.

Plist contents (spec "Agents" table): `Label`; `ProgramArguments`; `WorkingDirectory` `@REPO@`; `RunAtLoad` true on all three; poller only: `KeepAlive` true and `ThrottleInterval` 30; compact only: `StartCalendarInterval` `{Minute: 10}`; static only: `StartCalendarInterval` `{Hour: 4, Minute: 0}`; `StandardOutPath` and `StandardErrorPath` both the agent's log. Program arguments:
- poller: `/usr/bin/caffeinate`, `-i`, `@REPO@/.venv/bin/mbta-poller`, `--data-dir`, `@REPO@/data`
- compact: `@REPO@/.venv/bin/mbta-compact`, `--data-dir`, `@REPO@/data`, `--pending`
- static: `@REPO@/.venv/bin/mbta-static`, `--data-dir`, `@REPO@/data`

Each template starts with an XML comment, in English, saying it is a template rendered by `install.sh` and must not be edited once installed; the poller one also explains `caffeinate -i` and `ThrottleInterval` in one line each.

`install.sh`:
1. `ROOT` is the parent of the parent of the script's directory, resolved with `cd ... && pwd -P`.
2. If `ROOT` contains `&`, `<` or `>`: message to stderr, exit 1, nothing written.
3. Rendering: for each template, read it into a variable and replace with bash `${content//@REPO@/$ROOT}` (no sed, so any other character in the path is safe); write to `<target>/<label>.plist`.
4. `--render-only DIR`: create DIR, render into it, exit 0. No macOS check, no `.venv` check, no `plutil`, no `launchctl`, no git.
5. Full install (no arguments): require `uname` to be `Darwin`; require `$ROOT/.venv/bin/mbta-poller`, `mbta-compact`, `mbta-static` to be executable, else tell the user to run `uv sync`; `mkdir -p "$ROOT/data/logs"`; target is `$HOME/Library/LaunchAgents`; render; `plutil -lint` each file; if `git -C "$ROOT" branch --show-current` is not `main`, print a warning that the agents run whatever this checkout has checked out and that it should stay on `main`, then continue; for each label: `launchctl bootout "gui/$(id -u)/<label>" 2>/dev/null || true`, then `launchctl bootstrap "gui/$(id -u)" <plist>`; finally print each label with the `state =` line of `launchctl print "gui/$(id -u)/<label>"`.
6. Any other argument: usage to stderr, exit 2.

`uninstall.sh`: for each label, `launchctl bootout` (ignore "not loaded") and `rm -f` the plist in `$HOME/Library/LaunchAgents`; print what was removed; never touch `data/`.

`docs/operations.md`, sections in this order, each short, commands in `bash` blocks:
1. **What runs:** the three agents, their schedule, `caffeinate -i`, log files.
2. **Operating rule:** the checkout the agents are installed from stays on `main`; branch work happens in git worktrees (`git worktree add ../<dir> <branch>`); a dedicated runtime checkout is a later improvement.
3. **Install:** `uv sync`, then `ops/launchd/install.sh`; rerun after editing a template.
4. **Check:** `launchctl print gui/$(id -u)/io.github.eldiego5599.mbta.poller`, `launchctl list | grep mbta`, `tail -f data/logs/poller.log`, and the latest `data/fetch_log` file.
5. **Update the code:** `git pull && uv sync`, then `launchctl kickstart -k gui/$(id -u)/io.github.eldiego5599.mbta.poller`; batch agents pick up the new code on their next run.
6. **Run a job now:** `launchctl kickstart gui/$(id -u)/io.github.eldiego5599.mbta.compact` (same for static).
7. **Compaction details:** `--pending` compacts every closed hour with bronze and no silver, oldest first; a failed hour is retried every hour and shows in `compact.log`; it never recompacts an hour that already has silver, so a late snapshot only enters silver after a manual `uv run mbta-compact --data-dir data --hour YYYY-MM-DDTHH`; a manual `--hour` run at the same time as the agent can write the same hour twice, which is harmless because writes are atomic.
8. **Sleep:** `caffeinate -i` stops idle sleep on AC and on battery while the poller runs; the display still sleeps; lid closed, Sleep from the menu and critically low battery still sleep the Mac; nothing is fetched while asleep, gaps stay in `fetch_log` and are never filled; on wake the poller resumes its grid and the next compaction catches up.
9. **Uninstall:** `ops/launchd/uninstall.sh`; data is kept.
